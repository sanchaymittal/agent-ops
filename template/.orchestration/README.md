# .orchestration/ — dispatch evidence

Working records of multi-agent dispatches. Protocol: `docs/orchestration/index.md`.

- `prompts/TEMPLATE.md` — copy to `{{ISSUE_PREFIX_LOWER}}-xx-<role>-<slug>.md` and fill every field before dispatch. The prompt is immutable intent: a failed/hung worker is respawned from the same file in a fresh worktree.
- `reports/TEMPLATE.md` — copy to the same basename as its prompt. The worker records exact outcome, commands/exits, failures, deviations, final verification time, and diff SHA.
- `preflight.sh --verify-cmd CMD [--base-sha SHA] [--cli NAME] [--role NAME]` — run before a worker loads task context. Checks the worktree, base SHA vs HEAD, that the verify command's program exists, CLI availability, the role against the local roster, and that the writer lease is free. Local only: no network, no model APIs. Failures are `blocked: <capability|task|lease>: <detail>` with a non-zero exit.
- `lease.sh acquire --dispatch ID [--owner NAME]` / `release [--owner NAME] [--force]` / `status` — one writer per worktree, locked by an atomic `mkdir` of `.orchestration/.lease/` (gitignored, so a held lease never changes the diff SHA). A second owner is rejected and the first record is left untouched; release is owner-aware, is a no-op when no lease is held, and needs `--force` to break someone else's or a stale one. Nothing is ever auto-reaped — a PID that can be proven gone is reported as stale, not cleaned up, and a PID that cannot be checked is treated as live. The record holds the caller's PID (`$PPID`); a caller invoked through a transient wrapper sets `LEASE_PID` to the process that actually spans the dispatch. Values containing a newline are rejected, since the record is line-oriented.
- `verify.sh --diff-sha` — hashes tracked + untracked worktree changes while excluding prompt/report records, avoiding a self-referential report hash.
- `verify.sh reports/<file>.md` — rejects identity/scope mismatches, out-of-scope paths, non-zero verification, unresolved placeholders, edits made after the recorded hash, and a `done` report whose `Acceptance check` disagrees with its prompt or carries no evidence. The check is `run: <command>` or `artifact: <path>`; an artifact must exist in the worktree.
- `verify.sh --run-verify reports/<file>.md` — everything above, then re-runs the recorded `Verify command` at the repository root after the final edit, prints at most 32 KiB of output, and fails on a non-zero exit. The command runs as argv — no shell ever interprets it — and must pass a capability profile: a restricted character set (so pipes, lists, redirects, substitution, backgrounding, and quoting cannot appear), a program that is either a worktree-relative path or a bare name on the runner allowlist, and no word whose basename is a shell/interpreter wrapper, network utility, or destructive utility. Anything else is refused, not executed.
- `burn.py [--since YYYY-MM-DD] [--sessions] [--max-polls-per-task N]` — supervision-cost meter. Counts every tool call in the Codex rollout logs into one of POLL / WORK / DISPATCH / EDIT, and attributes each round-trip's tokens to the call that drove it — a round-trip with no preceding call lands in `<none>`. Then enforces the budget stated in `docs/orchestration/supervision.md`: at most 2 supervision calls per dispatched task. Token shares print as context, not as the budget. Read-only and local only — `verify.sh` exercises it against fixtures and never against your logs, so run it yourself when coordination feels expensive. Reads the Codex rollout schema only: a coordinator on another CLI is invisible to it, and `EDIT` counts the `apply_patch` tool, so patches applied through a shell land in `WORK`.
- `supervise.sh runtime ...` — durable runtime state machine. `dispatch` records outstanding workers; `peek` observes unread events; `claim` resumes once; `ack` consumes only after coordinator action. `worker_done`, `escalation`, `decision_gate`, `terminal_exit`, and explicit cancellation are the only wake event types. `supervise.sh fallback ...` enforces the single all-worker `check --wait --peek --timeout-ms 900000` wait and classifies harness yields separately from genuine Orca timeouts.
- `role-launch.sh --provider PROVIDER --role ROLE` — provider adapter. It emits the selected roster file's SHA and an inline role body unless a provider-specific launcher has independently proved native role resolution.
- `install-manifest.json`, `VERSION`, and `installer.py` — installation provenance. The root `init.sh --check TARGET` distinguishes locally modified managed files from untouched outdated files; `init.sh --upgrade TARGET` updates only untouched managed files and preserves local edits.
- Files here are immutable history once a dispatch completes. Do not retro-edit; stale doc paths inside old prompts are expected.
